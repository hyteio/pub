# OpenWire v12 — implementation reference for pub

Derived from the ActiveMQ client source, tag `activemq-6.2.0` (the interop suite now tests against
ActiveMQ 6.3.2, which speaks the same OpenWire v12): `org.apache.activemq.openwire.*`, the generated `openwire/v12/*Marshaller.java`,
`org.apache.activemq.command.*`, `util/MarshallingSupport.java`, the inactivity monitor in
`transport/`, and `ActiveMQConnectionFactory` / `ActiveMQSession` / `ActiveMQMessageConsumer`.
Per-command field layouts are in [`v12-layouts.txt`](v12-layouts.txt), generated by
[`extract_layouts.py`](extract_layouts.py) (`python3 extract_layouts.py <src>/org/apache/activemq Cmd1,Cmd2,...`).

pub implements **version 12, tight encoding preferred (loose as fallback), no marshal cache, size prefix
on** — and nothing else. Loose is always needed: the first `WireFormatInfo` is loose-encoded.

## Framing (`OpenWireFormat`)

```
int32 size (big-endian; bytes after this field)   -- omitted only if sizePrefixDisabled
byte  data-structure type                          -- 0 = null command
...   body, encoded by the type's marshaller
```

Unmarshalling enforces `maxFrameSize` from the prefix before reading the body.

## Negotiation (`renegotiateWireFormat`)

Both sides send `WireFormatInfo` first — **the client must not wait for the broker's**: Artemis's
multi-protocol acceptor detects the protocol from the client's first bytes and stays silent until then.
The format starts with **every flag false** (loose, no cache), so the first `WireFormatInfo` is always
loose-encoded. After both are exchanged:

| property | rule |
|---|---|
| version | `min(local, remote)` (ignoring values ≤ 0) |
| MaxFrameSize | min |
| TightEncodingEnabled, CacheEnabled, StackTraceEnabled, TcpNoDelayEnabled, SizePrefixDisabled | AND of both sides |
| MaxInactivityDuration | min of both (inactivity monitor) |

pub advertises version 12, `TightEncodingEnabled=true`, `CacheEnabled=false`, `StackTraceEnabled=false`:
tight whenever the broker agrees (both tested brokers do), never the cache. The Java client advertises `PROTOCOL_VERSION = 12`; a broker that negotiates below 12 is
an error for pub (decision: v12 only).

`WireFormatInfo` body: `byte[8] magic = "ActiveMQ"`, `int32 version`, `ByteSequence marshalledProperties`
(a primitive map). Keys: `StackTraceEnabled`, `CacheEnabled`, `TcpNoDelayEnabled`, `SizePrefixDisabled`,
`TightEncodingEnabled` (boolean); `MaxInactivityDuration`, `MaxInactivityDurationInitalDelay`
(sic), `MaxFrameSize` (long); `CacheSize` (int); `Host`, `ProviderName`, `ProviderVersion`,
`PlatformDetails` (string); `MaxFrameSizeEnabled` (boolean, not negotiated).

## Tight encoding (`BooleanStream`, `tightMarshal1/2`)

Same fields in the same order as loose (verified for all 61 v12 marshallers), but **every boolean** goes
into a bit stream written ahead of the data: field booleans, presence flags, the "ASCII only" flag of
strings, and the 2-bit size of longs. Frame body = bit stream + data.

| kind | bits | data |
|---|---|---|
| boolean | value | — |
| long | `00` = 0, `01` = u16, `10` = u32, `11` = i64 (u16/u32 read back **unsigned**) | 0/2/4/8 bytes |
| String | present, then ascii-only (all units 1..=127) | u16 length + raw bytes, or `writeUTF` (max 32766 bytes) |
| ByteSequence / byte[] | present | i32 length + bytes |
| nested object | present, + one "cached form" bit (always 0) for **marshal-aware** types (messages, WireFormatInfo) | type byte + body |
| object array | present | i16 count + nested objects |
| Throwable | present (+ string bits) | as loose |

Bit stream: bytes filled least-significant bit first, prefixed by its length — `n` if `n < 64`,
`0xC0 n` if `n < 256`, else `0x80` + u16. Java computes sizes in a first pass and writes in a second;
writing bits and data together in one pass yields identical bytes.

## Loose encoding primitives (`v12/BaseDataStreamMarshaller`)

| kind | encoding |
|---|---|
| int / short / byte / boolean | big-endian `DataOutput` primitives |
| long (`looseMarshalLong`) | `int64` |
| String | `bool present` + Java `writeUTF` (**u16 length + modified UTF-8**: U+0000 as `C0 80`, non-BMP as surrogate pairs) |
| ByteSequence / byte[] | `bool present` + `int32 length` + bytes |
| const byte array | raw bytes, fixed length |
| nested object | `bool present` + `byte type` + body |
| cached object | with cache disabled: same as nested object |
| object array | `bool present` + `int16 count` + nested objects |
| Throwable | `bool present` + class (String) + message (String) + [if StackTraceEnabled: `int16 n` × (class, method, file Strings, `int32 line`) + cause Throwable] |

Every command (`BaseCommand`) starts with `int32 commandId`, `bool responseRequired`.
No v12 marshaller branches on version (only `WireFormatInfo` writes the version number).

## Message bodies and properties

- **TextMessage content**: `MarshallingSupport.writeUTF8` = `int32 length` + modified UTF-8 (−1 = null).
  If `compressed`, the content is zlib/deflate (`DeflaterOutputStream`) of that.
- **BytesMessage content**: the raw bytes (deflated if `compressed`).
- **marshalledProperties**: primitive map = `int32 count` (−1 = null), then per entry
  `writeUTF name` + `byte type` + value. Types: 0 null, 1 boolean, 2 byte, 3 char, 4 short, 5 int,
  6 long, 7 double, 8 float, 9 string (`writeUTF`), 10 byte[] (`int32 len` + bytes), 11 map, 12 list,
  13 big string (`writeUTF8`). Strings with `length() >= 8191` chars use type 13.
  pub's typed properties map 1:1 onto these (bool, byte, short, int, long, float, double, string).

## Session behaviour to mirror (`ActiveMQConnection`, `ActiveMQSession`, …)

| step | Java client |
|---|---|
| ConnectionInfo | **sync** (waits for `Response`, bounded by `connectResponseTimeout`) |
| SessionInfo | async |
| ProducerInfo / ConsumerInfo | **sync** |
| message send | **async** iff no `sendTimeout` (≤ 0), not `alwaysSyncSend`, and (non-persistent or `useAsyncSend` or transacted); else sync (`sendTimeout` bounds the wait) |
| producer window | async sends add the message size to a window of `producerWindowSize` bytes; `ProducerAck(size)` from the broker releases it; senders block when full |
| consumer / producer / session RemoveInfo | async (consumer carries `lastDeliveredSequenceId`) |
| connection RemoveInfo | **sync**, bounded by `closeTimeout` (15000 ms) |
| ShutdownInfo | async, last |

**Sending** (`ActiveMQSession.send`, `ActiveMQMessageProducer`): the producer sets `producerId`,
`destination`, `messageId = MessageId(producerId, ++sequence)`, `persistent`, `priority` (default 4),
`timestamp` (unless disabled), `expiration = timestamp + ttl` (0 = never), and the message's own headers
(`correlationId`, `replyTo`, `type`, `groupID`, `groupSequence`). `ProducerInfo.windowSize` comes from
`producerWindowSize` unless a `producer.windowSize` destination option overrides it. The window counts
`Message.getSize()` = 1024 + marshalled properties + content bytes per async send. Compression
(`useCompression`): TextMessage content = zlib(`writeUTF8` bytes); BytesMessage content = `int32` original
length + zlib(bytes); `compressed = true`. JMS 2 delivery delay is unsupported in the Java OpenWire client;
ActiveMQ's scheduler reads the `AMQ_SCHEDULED_DELAY` long property instead.

The broker swallows failures of asynchronous sends (logged, no reply), so a final synchronous command —
pub uses the connection RemoveInfo — confirms only that the broker processed them.

**Destination options are applied by the client.** `ActiveMQDestination.setPhysicalName` strips `?opts`
from the name; `ActiveMQMessageConsumer` copies `consumer.*` options onto `ConsumerInfo` fields
(`prefetchSize`, `maximumPendingMessageLimit`, `dispatchAsync`, `selector`, `noLocal`, `exclusive`,
`retroactive`, `priority`, …) and **fails on unknown ones**. pub must send the bare physical name and do
the same mapping.

**Receiving** (`ActiveMQMessageConsumer`): ConsumerInfo starts from the factory (`prefetchSize`,
`maximumPendingMessageLimit`, `dispatchAsync`, `exclusiveConsumer`, `useRetroactiveConsumer`), then `consumer.*`
options, then the selector argument. Prefetch 0 means the client pulls: `MessagePull(timeout)`, where 0 waits
for a message and a positive timeout gets an empty `MessageDispatch` when it expires. A dispatched message is
dropped with an EXPIRED ack (6) when `consumerExpiryCheckEnabled` and `0 < expiration < now`. On close,
`RemoveInfo(consumer).lastDeliveredSequenceId` = broker sequence id of the last message handed to the
application (−1 if none); the broker returns later prefetched messages without incrementing their redelivery
counter. `JMSRedelivered` = `redeliveryCounter > 0`, `JMSXDeliveryCount` = counter + 1.

Decompression as Java reads it: TextMessage = `InflaterInputStream` read lazily (an unterminated stream
is fine as long as the text is complete — Artemis sends those); BytesMessage = read the `int32` length,
then `Inflater.inflate(new byte[length])` — only the first `length` bytes count, because the Java sender
deflates its whole backing buffer (`deflater.setInput(bytes.data)`), not just the content.

**Browsing** (`ActiveMQQueueBrowser`): a ConsumerInfo with `browser = true` and prefetch
`queueBrowserPrefetch` (500). The broker dispatches the queue's messages, then a `MessageDispatch` whose
message is null: the end of the browse. Acks (standard) only free prefetch room; nothing is consumed.

**Durable subscriptions**: ConsumerInfo with `subscriptionName` and `clientId` (the connection's) on a
topic; prefetch `durableTopicPrefetch` (100). `Session.unsubscribe(name)` sends
`RemoveSubscriptionInfo` (type 9: connectionId, `subcriptionName` [sic], clientId) synchronously. ActiveMQ
answers a missing subscription with `InvalidDestinationException`; Artemis too (its queue
`<clientId>.<name>` doesn't exist).

**Local transactions** (`TransactionContext`): a `LocalTransactionId` (connection id + per-connection
sequence from 1). `TransactionInfo` (type 7) BEGIN is sent asynchronously, COMMIT_ONE_PHASE and ROLLBACK
synchronously. Messages and acks in the transaction carry its id; transacted sends are always
asynchronous. Closing a session with an open transaction rolls it back.

**Destinations**: `DestinationInfo` (type 8) ADD / REMOVE, synchronous (`destroyDestination`); ActiveMQ
refuses REMOVE while consumers are attached. Listing (`DestinationSource`): consumers on the advisory topics
`ActiveMQ.Advisory.Queue` / `ActiveMQ.Advisory.Topic`; ActiveMQ replays a message per existing destination
whose `dataStructure` is a DestinationInfo (ADD), with no end marker. Artemis sends no destination
advisories over OpenWire; its management API answers a TextMessage to `activemq.management` with
properties `_AMQ_ResourceName` (`broker`, `address.<name>`), `_AMQ_OperationName` (`getQueueNames`,
`getAddressNames`) or `_AMQ_Attribute` (`routingTypes`), and a JSON array of parameters as the body; the
reply goes to the message's reply-to (a temporary queue: DestinationInfo ADD of a TempQueue named
`<connection id>:<n>`) with `_AMQ_OperationSucceeded` and the result as a JSON array. ActiveMQ's broker ids
are `ID:host-…`; Artemis's are UUIDs.

**Acks** (`MessageAck.ackType`): 0 delivered, 1 poison, 2 standard, 3 redelivered, 4 individual,
5 unmatched, 6 expired. pub acks each message after handing it to the sink (individual or standard with
first = last message id, count 1).

**Inactivity monitor**: read timeout = `min(local, remote MaxInactivityDuration)`; when nothing has been
written for a third of that, send `KeepAliveInfo` (responseRequired = false by default); answer a
`KeepAliveInfo` that has responseRequired with one that doesn't. Monitoring starts after
`MaxInactivityDurationInitalDelay`. 0 disables.

## Verified against real brokers

`protocols/openwire/tests/broker.rs` (opt-in, `--ignored`) sends pub's WireFormatInfo, decodes the
broker's, negotiates, decodes the tight-encoded BrokerInfo and gets a `Response` to a tight-encoded
ConnectionInfo. Passes against ActiveMQ 6.2.0 (offers cache, MaxFrameSize 100 MB) and Artemis
(OpenWire provider version 5.19.1, cache off, no frame limit); both negotiate version 12 + tight.

`pub send` was checked by reading messages back with ActiveMQ's own Java OpenWire client (`activemq browse`)
and JMX: TextMessage bodies with non-BMP characters, typed properties, priority/type/correlation id/expiry,
compressed text and bytes bodies (also via Artemis), topics, 50 async sends through a 4 KiB producer window
(both brokers send ProducerAck), and Artemis scheduling a message from `AMQ_SCHEDULED_DELAY`.

`pub recv` was checked against messages from a Java producer (`ActiveMQConnectionFactory`, all eight property
types, JMSX group fields, reply-to, TTL, priority, Text/Bytes/Map messages, with and without
`useCompression`) on both brokers; pub → Java consumer; prefetch 3 with `-n 1` leaving the rest
unredelivered; selectors (Artemis reports a bad one as `ActiveMQInvalidFilterExpressionException`); prefetch-0
pulls; topics; and STOMP ⇄ OpenWire on ActiveMQ.
